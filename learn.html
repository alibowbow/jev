확률이 영업에 모여 있습니다. 되돌릴 수 있는 라벨 제안부터 연결해 볼 수 있어요.

실제 실행 기준은 작업별 평가로 정합니다.

선택지 확률과 확신도는 다른 지표막대는 선택지별 확률입니다. Choice·Score의 confidence는 분포의 모양에서 별도로 계산됩니다.

높은 확신 ≠ 정답 보장누락된 정보나 잘못된 기준 때문에 틀릴 수 있습니다. 의료 판단을 자동 실행할 근거로 쓰지 않습니다.

05 / JEV & GENERATIVE LLMs

LLM과는 무엇이 다를까요?

Jev는 정해 둔 질문의 판단에, 생성형 LLM은 설명·글쓰기·복잡한 문제 풀이에 초점이 있습니다.

같은 AI라도, 맡기려는 일이 다릅니다.
비교할 점Jev생성형 LLM
답의 형태선택지, 점수, 참일 확률처럼 미리 정한 형태문장·코드·요약문. 지원 모델은 JSON 등 정해진 형식도 가능
잘 맞는 일문의 분류, 후보 선택, 기준별 평가를 반복하는 작업대화, 글쓰기, 코딩, 설명과 여러 단계의 문제 해결
추론 방식긴 추론 문장을 생성하는 대신, 주어진 상태를 평가해 판단을 반환모델·설정에 따라 추론 토큰을 사용. 모든 LLM 응답이 긴 추론을 거치는 것은 아님
여러 질문같은 상태에 대한 독립 질문을 한 요청에서 병렬 평가여러 항목을 묶어 답하거나 요청을 병렬 처리할 수 있으나, 일반적인 텍스트 출력은 토큰을 순차 생성
불확실성Choice·Score는 선택지별 확률과 confidence, Noul은 참일 확률 반환직접 말한 ‘확신도’의 의미는 별도 검증 필요. 모델·API별로 제공 기능이 다름
한계와 오류정해진 출력 형식을 지켜도 판단 내용은 틀릴 수 있음. 자유로운 글쓰기는 맡기지 않음형식 제약을 지원하더라도 내용의 정확성을 보장하지 않음. 생성 결과와 실행 도구를 검증해야 함
속도·비용작고 반복적인 판단에 유리하도록 설계. 아래의 공개 수치·단가 참고소형부터 대형까지 차이가 큼. 짧은 출력·캐시·배치·추론 설정에 따라 달라짐

“Jev는 아무 생각도 안 하는 AI”라는 뜻은 아닙니다. 입력을 평가하는 추론은 합니다. 복잡한 일을 작은 판단과 코드로 나눠 구성하는 방식에 가깝습니다.

위 막대는 TypeSafe 홈페이지에 표시된 한 건의 시연 결과입니다. 발표문은 나란히 비교한 데모에 GPT-5.6 Terra의 기본 추론 설정을 사용했고, 짧고 밀도 높은 입력이 Jev에 유리하다고 설명합니다. 독립 재현한 결과는 아닙니다.

실제 선택에는 같은 입력·질문·정확도 기준으로 완료 시간과 느린 요청 구간(p95)을 비교하세요. LLM의 ‘첫 토큰이 보일 때까지’와 Jev의 ‘판단 완료’를 같은 속도로 취급하면 안 됩니다. OCR, 검색, 클릭, 네트워크, 재시도 시간도 앱 전체 시간에 더해집니다.

단가 × 토큰 수 · 실제 API 호출 없음

입력에는 본문·지시문·질문·선택지를 포함하세요. LLM 출력에는 과금되는 추론 토큰도 포함합니다. Jev는 출력 과금이 없어 이 출력 설정이 적용되지 않습니다.

계산식과 포함하지 않은 비용

모델별 비용 = 건수 × (건당 입력 토큰 × 입력 단가 + 건당 과금 출력 토큰 × 출력 단가) ÷ 1,000,000. Jev의 출력 단가는 0입니다. 모델마다 토큰화·프롬프트·질문 구성은 달라질 수 있습니다.

OCR·음성 인식·검색·서버·도구 사용료, 재시도, 검토 인건비, 세금은 포함하지 않습니다. 호출 제한과 과금 방식도 실제 제공 경로에서 확인하세요. Jev로 먼저 분류하고 일부만 LLM에 넘기면 두 단계의 비용을 합산해야 합니다.

08 / GOOD TO KNOW

처음 궁금해지는 것들.

Jev가 직접 웹사이트를 클릭하나요?

페이지의 버튼 목록이나 상태를 앱이 전달하면 Jev가 후보를 고릅니다. 실제 클릭은 브라우저 도구나 앱 코드가 실행합니다. 따라서 판단 모델과 실행 도구를 함께 연결해야 합니다.

영상이나 사진을 바로 읽을 수 있나요?

이 가이드의 Jev는 텍스트와 구조화된 상태를 입력으로 다룹니다. 화면·음성 데모는 OCR, 음성 인식, 별도의 시각 모델 등이 정보를 텍스트나 상태로 바꾸는 과정을 함께 사용합니다.

출력 형식이 정해져 있으면 항상 맞나요?

형식이 맞는 것과 내용이 맞는 것은 다릅니다. 선택지를 빠뜨리거나 입력에 정보가 부족하면 잘못 판단할 수 있습니다. ‘기타·알 수 없음’을 마련하고 실제 데이터로 점검하세요.

처음에는 무엇부터 만들면 좋을까요?

메일 분류처럼 입력과 정답 기준을 쉽게 모을 수 있는 작업 하나로 시작하세요. 기존 규칙과 비교하고, 처리 시간·전체 비용·오분류를 함께 기록하면 도입할 가치가 있는지 판단하기 좋습니다.
