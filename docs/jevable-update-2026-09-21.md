# Jevable selection — 2026-09-21

Reviewed the 194 projects listed across Jevable's six public directory pages and selected 50 additions with distinct applications. The catalogue now contains 86 cases across eight categories, including a new robotics/simulation category. Existing case IDs remain unchanged for bookmarks and shared links.

Selection favors concrete, varied workflows: document routing, adaptive forms, design tools, simulation, developer tools and data preparation. Repetitive game demonstrations and insufficiently substantiated clinical proposals were excluded. The existing two medical/dental implementation ideas are unchanged.

Descriptions are independently edited in Korean from the public project records and their displayed original-post text. Truncated posts are not extrapolated; numerical accuracy/speed superiority claims are omitted where context is missing. Jev's decision step is distinguished from transcription, rendering, code generation, OCR and physical execution. Simulations are labeled accordingly.

## Media and source checks

All 50 project detail pages returned HTTP 200 and contained the linked original publisher post URL. All 50 original-publisher video files returned HTTP 200 with a video content type. Prefer a publisher-provided 720p rendition where available; retain the source's aspect ratio. These are availability checks, not a claim to have watched all videos or reproduced reported performance.

No videos, thumbnails or directory descriptions are copied into the repository. Original CDN URLs are loaded on demand, with retry and the original post always available. Initial browsing loads only lazy thumbnails. The runtime allows the exact video.twimg.com hostname in addition to the existing raw.githubusercontent.com host.

26 poster HEAD requests returned HTTP 200; 24 returned HTTP 403. Original public thumbnail URLs are retained with the existing image-error fallback; browser availability can differ. No restricted media was retrieved.

Duplicate checks compare original post URLs and underlying video IDs across all 86 cases, including different-resolution variants. Search includes the original project name and tags.

## Post-deployment browser checks

The public site displayed 86 cards, original-name search returned Drape, and the robotics filter returned four cases. The Drape MP4 played directly in the browser (31.3 seconds, 1278-pixel video width); the first embedded attempts did not complete. The existing flight MP4 played in-page. To accommodate slow initial CDN loads, native MP4 loading allows 45 seconds, with an always-available direct-file link alongside the original post. Availability checks do not establish universal embedded playback.

## Playback correction after the user report

The initial direct-CDN implementation was not reliable: the Drape and Proq video requests later returned HTTP 403, and the in-page failure reproduced. Increasing the timeout and exposing a direct-file link did not solve the issue. Historical HTTP 200 checks above only describe that earlier observation.

All 50 additions now use the existing official X widget path keyed by the original post ID. Captured CDN rendition URLs have been removed from the catalogue and from the native-player allowlist. No proxy, referrer spoofing or rehosting is used. The full catalogue is now 84 official X embeds plus the two existing publisher-hosted GitHub MP4s. Regression coverage walks every new card, checks the exact post requested, confirms the absence of a native video or stale direct-file link, and verifies iframe cleanup when closing.
